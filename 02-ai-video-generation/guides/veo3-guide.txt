## 1. PERSONAL CHANNEL (CHANNEL A) — NO ROTATION NEEDED

   Your personal channel uses a standard Google OAuth2 account:
   - Once authorized, it remains linked permanently.
   - n8n automatically handles refreshing the OAuth token behind the scenes.
   - You do NOT need to rotate, log out, or change keys for Channel A.

---

## 2. AI CONTENT CHANNEL (CHANNEL B) — ROTATING CREDITS ($0 STRATEGY)

   Since Vertex AI VEO3 is paid (~$3 per video), using a new Google Cloud (GCP) 
   account with a fresh $300 trial credit is the best way to keep it free.

   When credits run out on Account #1:
   1. Create a new Google Account (Account #2).
   2. Enable Google Cloud & Vertex AI API (you get a fresh $300 credit).
   3. Open the "Setting" node in the VEO3 workflow.
   4. Update:
      - PROJECT_ID   → set your new GCP Project ID
      - ACCESS_TOKEN → set your new CLI Bearer Token
        (Run: gcloud auth print-access-token on your local CLI)

---

## 3. AUTOMATED TELEGRAM EXPIRATION ALERTS

   If a token expires or credits are exhausted mid-run, the workflow will
   NOT crash silently.

   How it works:
   ┌────────────────────────────────────────────────────────┐
   │ Vertex AI request fails (401 Unauthorized or Credit limit)│
   └──────────────────────────┬─────────────────────────────┘
                              ▼
   ┌────────────────────────────────────────────────────────┐
   │ Error Trigger node catches the failure immediately     │
   └──────────────────────────┬─────────────────────────────┘
                              ▼
   ┌────────────────────────────────────────────────────────┐
   │ Telegram Alert on Error sends you a message:           │
   │ "⚠️ VEO 3 generation failed! Access Token or credits  │
   │  expired. Please update the Setting node in n8n."      │
   └────────────────────────────────────────────────────────┘

---

## 🛠️ HOW TO UPDATE CREDENTIALS WHEN EXPIRED

   When you receive the Telegram error notification:

   ### Step A: Generate a new GCP Bearer Token (lasts 60 minutes)
   If you are running manually:
   1. Open terminal on your computer.
   2. Run command:
      ```bash
      gcloud auth print-access-token
      ```
   3. Copy the long string starting with `ya29...`

   ### Step B: Paste the new token into n8n
   1. Open http://localhost:5678
   2. Open the "My workflow 2" workflow.
   3. Open the node named "Setting".
   4. Locate the field `ACCESS_TOKEN`.
   5. Delete the old token and paste the new `ya29...` token.
   6. Click "Save".

   ### Step C (Alternative): Use a Service Account (Permanent)
   To avoid rotating tokens every hour, you can generate a Service Account JSON
   key in Google Cloud IAM, upload it to your Docker container, and use an HTTP 
   request to auto-fetch the token.
